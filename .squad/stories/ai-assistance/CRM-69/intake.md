## Source — work item (from tracker)

**Title:** AI-002 — Ticket Summary & Categorization  
**Type:** Task  
**Status:** In Progress

### Description

User Story

As a support agent, I want AI to summarize a ticket and suggest a category so that I can understand customer issues faster and classify tickets consistently.

Objective

Add two AI-assisted capabilities:

	Ticket summary

	Automatic category suggestion

AI output must always be treated as a suggestion, not an unquestioned business decision.

The agent must be able to review and accept or ignore the suggestion.

Scope

This story covers:

	Ticket summary generation

	Ticket categorization suggestion

	AI context preparation

	Structured AI response

	Output validation

	Apply/ignore actions

	Agent UI

	Error handling

	AI provider abstraction from AI-001

	Authorization

	Tests

This story does not cover:

	Suggested replies

	Suggested solutions

	AI chatbot

	Automatic ticket reassignment

	Automatic category changes without review

Those belong to later stories.

Part 1 — Ticket Summary

User Flow

Agent opens ticket
      ↓
AI Summary
      ↓
[Generate Summary]
      ↓
.NET prepares ticket context
      ↓
IAiService
      ↓
AI response
      ↓
Validate response
      ↓
Display summary

Ticket Context

The AI should receive only relevant information.

Recommended:

Ticket Subject
Ticket Description
Priority
Status
Category
Customer messages
Agent messages
Relevant ticket history

Do not send unnecessary information.

Do not send:

	Passwords

	Authentication tokens

	API keys

	Internal credentials

	Unrelated customer data

Summary UI

Add a section to the ticket details page:

┌──────────────────────────────────────────┐
│ AI Summary                               │
│                                          │
│ Customer is unable to access their       │
│ account after resetting their password.  │
│ The customer attempted the reset twice   │
│ without receiving the confirmation email.│
│                                          │
│ Generated by AI                          │
│                         [Regenerate]      │
└──────────────────────────────────────────┘

If no summary exists:

AI Summary

Get a quick summary of this ticket.

[Generate Summary]

Summary Rules

The summary should be:

	Concise

	Factual

	Based only on ticket context

	Free of invented information

	Easy for an agent to understand

The AI should not make unsupported claims.

Summary Storage

For the MVP, the generated summary may be returned to the frontend without permanent storage.

Recommended first implementation:

Generate Summary
      ↓
AI
      ↓
Return Summary

Do not add a summary table unless the SDD requires persistence.

If persistence is needed later, create a dedicated AI-result model rather than adding AI fields directly to Ticket.

Regeneration

The agent can request a new summary.

Example:

[Regenerate]

The backend should regenerate using the latest ticket context.

Do not automatically regenerate on every ticket message.

Part 2 — Automatic Categorization

User Flow

Ticket Created
      ↓
Agent opens ticket
      ↓
[Suggest Category]
      ↓
AI analyzes ticket
      ↓
Suggested category
      ↓
Agent reviews
      ↓
[Apply] [Ignore]

For the 2-day assessment, manual trigger is recommended.

Do not automatically call AI for every ticket creation because this creates unnecessary cost and complexity.

Category Suggestion

Example:

AI Suggested Category

Technical Support

Confidence:
High

[Apply] [Ignore]

The confidence value should only be displayed if the AI/provider supplies a meaningful confidence value.

Do not invent a numeric confidence score.

Structured Response

The AI should return structured data.

Example:

{
  "categoryId": "category-id",
  "categoryName": "Technical Support",
  "reason": "The ticket describes a login and account access problem."
}

The backend must validate the returned category.

Category Validation

Important:

AI
 ↓
Suggested categoryId
 ↓
Backend
 ↓
Does category exist?
 ↓
Is category active?
 ↓
Is category allowed?
 ↓
Return suggestion

The AI must not be allowed to create a category.

Applying Suggestion

When the agent clicks:

[Apply]

the frontend should call a normal ticket/category API.

Example:

PATCH /api/tickets/{id}/category

The backend applies normal authorization and validation.

Do not create:

POST /api/ai/apply-category

if the existing ticket category API can be reused.

AI should suggest.

The normal business API should apply.

Ignore

Clicking:

[Ignore]

should simply dismiss the suggestion.

No ticket data should change.

Automatic Categorization

Despite the feature name, the MVP should use:

AI-assisted categorization

rather than:

AI-controlled categorization

This is safer and better demonstrates human verification.

Automatic application can be added later if explicitly required.

API

Generate Summary

Recommended:

{{POST /api/ai/tickets/

{ticketId}/summary}}

Example response:

{
  "summary": "Customer is unable to access their account after resetting their password.",
  "provider": "Development"
}

The backend should:

# Authenticate user.

# Authorize ticket access.

# Load ticket context.

# Prepare AI input.

# Call IAiService.

# Validate result.

# Return summary.

h2. Suggest Category

Recommended:

{{POST /api/ai/tickets/{ticketId}
/category-suggestion}}

Example:

{
  "categoryId": "category-id",
  "categoryName": "Technical Support",
  "reason": "The ticket describes an account access issue."
}

Apply Category

Use the normal ticket category API.

Example:

{{PATCH /api/tickets/

{ticketId}
/category}}

{
  "categoryId": "category-id"
}

The backend must validate:

	Category exists

	Category is active

	User has permission

	Ticket exists

AI Service

Reuse:

IAiService

from AI-001.

Do not create:

ITicketSummaryAiService
ICategorizationAiService

unless the SDD specifically requires separate interfaces.

A feature-specific application service can call the common AI provider.

Example:

TicketAiService
      ↓
IAiService

Prompt Design

The AI prompt should explicitly define the task.

For summary:

Summarize the following customer support ticket.

Rules:
- Use only the provided information.
- Do not invent facts.
- Keep the summary concise.
- Focus on the customer's issue and relevant actions already taken.

For categorization:

Classify the support ticket using only the provided categories.

Return only a valid category from the supplied category list.

Do not create a new category.

The exact prompt should be maintained in the AI application layer.

Do not scatter prompts throughout controllers.

Category Context

The categorization request should include the available categories.

Example:

Available categories:

1. Account & Security
2. Technical Support
3. Payments
4. Orders
5. General Inquiry

The AI must select from these values.

Do not let the AI invent:

"Password Problems"

when that category does not exist.

Output Validation

AI output must be validated before returning it to the frontend.

Example:

AI says:
categoryId = abc123

Backend:
Does abc123 exist?
       ↓
Yes
       ↓
Is active?
       ↓
Yes
       ↓
Return suggestion

If invalid:

AI returned an invalid category.

Do not apply it.

Hallucination Protection

The AI must not be treated as the source of truth.

Examples:

AI:
Customer is VIP

Database:
Customer is not VIP

The system should not update the customer record based on the AI statement.

Similarly:

AI:
Category = Payments

must be validated against the actual database.

Do not make the UI misleading.

Human Verification

This is an important requirement for the assessment.

AI output should have:

Suggestion

not:

Decision

The agent reviews the result.

Example:

AI Suggested Category
Technical Support

[Apply] [Ignore]

This demonstrates responsible AI usage.

Authorization

Use AUTH-003.

The AI endpoints must enforce the same ticket access rules as the ticket itself.

Example:

Agent cannot access ticket
       ↓
Agent cannot generate AI summary

Do not create a shortcut around ticket permissions.

Privacy

Only provide the minimum ticket information required.

Before sending content to an external AI provider, the implementation should consider:

	Customer personal information

	Contact information

	Internal notes

	Sensitive information

For the MVP, document the data passed to the provider.

Do not silently send the entire customer profile.

Internal Notes

Be careful with internal notes.

For ticket summaries, internal notes may be useful to the agent.

However, the AI result must never expose internal notes to customers.

AI output generated for the agent belongs to the CRM agent experience.

The Customer Portal must not automatically receive it.

Performance

Do not generate AI output automatically on every ticket page load.

Bad:

Agent opens ticket
 ↓
AI automatically called

Recommended:

Agent opens ticket
 ↓
[Generate Summary]

This reduces:

	AI calls

	Cost

	Latency

	Unnecessary provider usage

Rate Limiting

Do not allow unlimited AI requests.

For MVP, the existing API rate-limiting strategy should apply.

If none exists, avoid implementing a complex AI quota system.

At minimum, prevent accidental request loops from the frontend.
